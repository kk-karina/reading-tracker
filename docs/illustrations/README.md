# Иллюстрации пустых состояний

Исходные листы — `sheet-01.png` (1536×1024, шесть рисунков сеткой 3×2 на
белом) и `sheet-02.png` (тот же размер, один рисунок на прозрачном). Из
приложения они не импортируются: в бандл идут нарезанные штуки из
`src/assets/empty/`. Листы лежат здесь затем, чтобы нарезку можно было
повторить — с другим кадрированием, в другом размере или после правки.

## Что получилось

| Файл | Рисунок | Где стоит |
| --- | --- | --- |
| `reading.png` | лежит с книгой, рядом цветок | полка, сессии книги, «нет книг», «ничего не простаивает», пустой бэклог |
| `writing.png` | пишет на листке среди бумаг | дневник, мысли, конспекты, лента конспектов |
| `pile.png` | навалился на стопку книг | год в книгах, очередь на дашборде, «ничего не изучается» |
| `signpost.png` | указатель и карта в руках | хаб потоков, «книга не найдена», «нет главной книги» |
| `laptop.png` | ноутбук и шапочка в мыслях | части материала, «пройденного пока нет» |
| `box.png` | открывает коробку, рядом пёс | материалы потока — и больше нигде |
| `waiting.png` | лежит с книгой перед пустым графиком | «страниц по неделям», пока недели пусты |

Имена — про то, чем герой занят, а не про экран: «пишет» годится и мыслям о
книге, и конспекту занятия. Один рисунок может стоять в нескольких местах, и
это нормально, пока места про одно и то же; собачка с коробкой — исключение,
её держат за одним разделом нарочно.

## Как нарезано

Границы найдены по пустым полосам между рисунками, не на глаз: лист
переводится в маску «не белое» и у неё ищутся сплошные белые коридоры по
строкам и столбцам. Отсюда и рамки:

```
reading   (56, 140, 568, 495)      signpost  (45, 547, 509, 906)
writing   (588, 140, 992, 495)     laptop    (558, 547, 974, 906)
pile      (1041, 140, 1489, 495)   box       (1011, 547, 1486, 906)
```

Дальше с каждым куском происходит три вещи.

**Белое становится прозрачным — везде, включая тело героя.** Это не
аккуратность ради аккуратности: страницы приложения стоят на `--bg`, а не на
белом, и рисунок с белой подложкой был бы заплаткой. Прозрачный герой — то же,
чем он выглядит на белом листе исходника, и ровно то, как пак показан в
оригинале.

Прозрачность считается не порогом, а так: `alpha = max(255 - max(r,g,b),
sat * 1.6)`. Первое слагаемое ловит чернила (чёрное непрозрачно, белое
прозрачно), второе — лимон (он светлый, но насыщенный, и порогом по яркости
отрезался бы вместе с фоном). Потом из цвета вычитается подложенный белый
(`C = (src - 255*(1-a)) / a`), иначе полупрозрачные края пришли бы на страницу
размытыми.

**Низ альфы срезается.** Всё ниже 36 — это мягкая тень самого исходника, и на
странице она читается дымкой вокруг рисунка.

**Цвет сводится к двум.** Рисунок и состоит из чернил и лимона; тысяча
промежуточных оттенков в полупрозрачных пикселях ничего не добавляет глазу и
вчетверо раздувает PNG. Чернила берутся из `--ink`, лимон — из пака. Форму
несёт альфа, и она же округляется до ступеней по 8.

Шесть файлов после этого весят 186 КБ на все.

## Повторить нарезку

Нужен Python с Pillow и numpy. Скрипт короткий и лежит целиком здесь, чтобы
не заводить в проекте ветку инструментов ради одной операции:

```python
from PIL import Image
import numpy as np, os

SRC, OUT, PAD, FLOOR = 'docs/illustrations/sheet-01.png', 'src/assets/empty', 10, 36
INK = np.array([14, 16, 18], dtype=np.float64)
LEMON = np.array([217, 242, 74], dtype=np.float64)
CELLS = {
    'reading': (56, 140, 568, 495), 'writing': (588, 140, 992, 495),
    'pile': (1041, 140, 1489, 495), 'signpost': (45, 547, 509, 906),
    'laptop': (558, 547, 974, 906), 'box': (1011, 547, 1486, 906),
}

full = np.asarray(Image.open(SRC).convert('RGB')).astype(np.float64)
for name, (x0, y0, x1, y1) in CELLS.items():
    a = full[y0:y1, x0:x1]
    sat = a.max(axis=2) - a.min(axis=2)
    alpha = np.clip(np.maximum(255.0 - a.max(axis=2), np.minimum(255.0, sat * 1.6)), 0, 255)
    alpha = np.clip((alpha - FLOOR) * (255.0 / (255.0 - FLOOR)), 0, 255)
    ys, xs = np.nonzero(alpha > 12)
    ty0, ty1 = max(0, ys.min() - PAD), min(alpha.shape[0], ys.max() + 1 + PAD)
    tx0, tx1 = max(0, xs.min() - PAD), min(alpha.shape[1], xs.max() + 1 + PAD)
    alpha, sat = alpha[ty0:ty1, tx0:tx1], sat[ty0:ty1, tx0:tx1]
    rgb = np.where((sat > 45)[:, :, None], LEMON, INK)
    alpha = (np.round(alpha / 8.0) * 8).clip(0, 255)
    Image.fromarray(np.dstack([rgb, alpha]).astype(np.uint8), 'RGBA').save(
        os.path.join(OUT, f'{name}.png'), optimize=True)
```

## Второй лист

`sheet-02.png` пришёл уже прозрачным, но с полупрозрачной заливкой внутри
экрана графика. Поэтому перед тем же расчётом альфы он кладётся на белое —
и становится таким же листом, как первый. Рисунок занимает лист целиком,
так что рамка одна, `(120, 161, 1446, 824)`, а масштаб приводится к паку
(высота 352) до расчёта альфы, а не после: иначе уменьшение вернуло бы
промежуточные ступени, которые расчёт только что свёл.

```python
src = Image.open('docs/illustrations/sheet-02.png').convert('RGBA')
flat = Image.alpha_composite(Image.new('RGBA', src.size, (255,) * 4), src).convert('RGB')
flat = flat.crop((120, 161, 1446, 824))
flat = flat.resize((round(flat.width * 352 / flat.height), 352), Image.LANCZOS)
# дальше — тот же расчёт альфы и цвета, что в скрипте выше, сохранить как waiting.png
```

## Аватары

`sheet-03.png` (1536×1024) — двадцать аватаров сеткой 5×4, каждый в
лимонном круге на белом. Нарезаны в `src/assets/avatars/`, по 192 px в webp,
все вместе около 170 КБ. Имена и порядок сетки — `AVATAR_IDS` в
`src/lib/avatars.ts`, картинки к ним — `AVATAR_SRC` в
`src/components/Avatar.tsx`.

Здесь, в отличие от пустых мест, белое не убирается: у аватара белое тело
героя — часть рисунка, а форму задаёт сам круг. Поэтому кусок вырезается
кругом, а не по альфе.

**Как найден круг.** Маска лимона (`r > 190, g > 220, b < 170`), из центра
клетки по 720 лучам берётся самая дальняя лимонная точка, по ним
наименьшими квадратами подбирается окружность, а точки, отстоящие от неё
больше чем на 2,5 px, отбрасываются, и так шесть раз. Отбрасывать нужно:
по низу круг закрывает белое тело, сбоку — волосы и руки, и эти лучи
обрываются раньше края. Вырезается на пиксель внутрь найденного радиуса,
чтобы не тащить белую кайму.

У `hair` (длинные волосы закрывают половину края) подбор не сошёлся, и
круг для него найден только по верхнему и правому краю лимона:
`(465.2, 632.0)`, радиус 106.7.

```python
from PIL import Image, ImageDraw
src = Image.open('docs/illustrations/sheet-03.png').convert('RGB')
OUT, big = 192, 4
mask = Image.new('L', (OUT * big,) * 2, 0)
ImageDraw.Draw(mask).ellipse((0, 0, OUT * big - 1, OUT * big - 1), fill=255)
mask = mask.resize((OUT, OUT), Image.LANCZOS)
for name, (cx, cy, r) in CIRCLES.items():  # таблица выше
    r -= 1
    a = src.crop((cx - r, cy - r, cx + r, cy + r)).resize((OUT, OUT), Image.LANCZOS).convert('RGBA')
    a.putalpha(mask)
    a.save(f'src/assets/avatars/{name}.webp', quality=88, method=6)
```
