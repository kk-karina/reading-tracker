# Материалы лернинга — дизайн

Дата: 2026-09-22. Статус: на утверждении.

У материала лернинга сегодня одна форма на все виды: единственное поле прогресса
`parts_total` и правило «глава пройдена, если по ней есть конспект». Из-за этого
статью нельзя закрыть в принципе, у видео нет отметки «посмотрела», а курс не
умеет ничего, кроме числа.

Спека делает форму материала зависящей от вида, заменяет число частей настоящим
списком, подключает уже написанное и мёртвое сегодня автозаполнение по ссылке и
чинит попап добавления вместе с общими элементами, на которых он собран.

Опирается на `2026-09-20-learning-hub-design.md` (потоки, бэклог, статусы) и
`2026-09-21-two-section-ia-design.md` (адреса и вложенность). Ни то, ни другое не
переопределяется.

## 1. Что не так сейчас

| Симптом | Причина в коде |
|---|---|
| Статью невозможно закрыть | `materialProgress` считает пройденным то, по чему есть конспект (`src/lib/learning/metrics.ts`). У цельной статьи глав нет, значит нет и способа отметить её прочитанной |
| Курс — это одно число | `Material.parts_total: number \| null`. Лекции не названы, отметить конкретную нельзя |
| Книга в лернинге ничего не умеет | Того же поля `parts_total` хватает на «12 из 20», но не на страницы |
| Ссылка ничего не даёт | `src/lib/learning/cover.ts` целиком умеет YouTube, Open Graph через microlink и догадку вида по домену. Есть тесты. `MaterialForm` про это не знает — там голый инпут. Строки `material.fetch`, `material.fetching`, `material.fetchNothing`, `material.fetchHint`, `material.cover`, `material.coverClear` лежат в словаре неиспользованными |
| Обложку нельзя задать руками | Поле `cover_url` заполняется только вручную набранным адресом; загрузки файла нет |
| Материал добавляется только из бэклога | На дашборде потока кнопки нет — только ссылка в шапке зоны |
| Подкаст и «другое» ничего не значат | Два вида без собственного поведения, отличающиеся только значком |
| Поля в попапе стоят вплотную | `.sheet` не задаёт `gap` детям. `BookForm`, `SessionSheet`, `StudySheet` оборачивают поля в `.book-form` (`flex-column; gap:16px`), а `MaterialForm` и `StreamForm` — нет |
| Автор и число глав не встают в ряд | `.form-row` объявлен как `display:grid; gap:12px` без `grid-template-columns` (`src/index.css:420`). Рядом живёт `.field-row`, который делает то же самое правильно |
| Чипсы разной высоты | `.chip` задаёт `height:32px` и `padding:0 12px`, но не задаёт `display`. На `<button>` работает, на `<span>` — нет: у инлайн-элемента высота и вертикальные отступы игнорируются |
| Попап не модальный | `Sheet` ставит `role="dialog"` и `aria-modal`, но фокус не заперт, при открытии не переносится, при закрытии не возвращается, страница под шимой скроллится |

Общий знаменатель последних четырёх строк: **общие элементы существуют классами, а
не компонентами**. Класс можно забыть поставить, можно поставить на неподходящий
тег — что и произошло в обоих случаях.

## 2. Ключевые решения

**Вид материала определяет его поля.** Четыре вида, у каждого своя шкала прогресса.
`podcast` и `other` убираются: собственного поведения у них нет.

**Отметка о прохождении становится явной.** Прежнее правило «есть конспект — значит
пройдено» разворачивается. Оно стояло на мысли, что потребление и обучение это не
одно и то же, и мысль верна, — но следствием было то, что закрыть статью нельзя
вообще. Теперь это две независимые величины: пройдено и записано.

**Части — отдельная коллекция.** Главы книги и лекции курса живут списком рядом с
материалами и конспектами, а не полем внутри материала. У части есть `id`. Это ровно
та форма, которой станет таблица в Supabase, и за этот `id` позже зацепится конспект.

**Книга выбирает шкалу при добавлении.** Страницы или главы, не обе сразу.
Переключатель явный, потому что вывести его из заполненного нельзя: пустое поле
«глав» одинаково значит и «глав нет», и «не знаю сколько».

**Материал лернинга — своя сущность.** Книга в потоке и книга на Полке не связаны.
Одна и та же книга может лежать и там, и там, и это два независимых объекта.

**Автозаполнение не затирает введённое.** Заполняются только пустые поля. Ручной
ввод остаётся полноправным путём, а не запасным.

**UI-кит не берём.** Ни shadcn, ни Tailwind, ни Radix. Причина: shadcn требует
Tailwind, а это переписывание 3900 строк CSS и всего своего визуального языка.
Нужное от shadcn — не библиотека, а привычка: не класс, а компонент. Это делается
здесь тремя компонентами.

## 3. Модель данных

### Виды

```ts
export const KINDS = ['book', 'article', 'course', 'video'] as const
export type MaterialKind = (typeof KINDS)[number]
```

`MaterialStatus` не меняется: `inbox | active | someday | reference | done | dropped`.

### Материал

```ts
/** Чем меряется книга. У остальных видов шкала одна, и вопроса не возникает. */
export type BookScale = 'pages' | 'parts'

export interface Material {
  id: string
  stream_id: string
  title: string
  kind: MaterialKind
  author: string | null
  url: string | null
  status: MaterialStatus
  cover_url: string | null
  /** Только у книги: по страницам или по главам. У остальных null. */
  scale: BookScale | null
  /** Только при scale === 'pages'. */
  pages_total: number | null
  page_current: number | null
  sort: number
  created_at: string
  updated_at: string
}
```

`parts_total` удаляется.

### Часть

```ts
/**
 * Глава книги или лекция курса. Один список на оба вида: разница между ними
 * только в слове, которым это называют на экране.
 */
export interface MaterialPart {
  id: string
  material_id: string
  title: string
  done: boolean
  sort: number
}
```

`LearningSnapshot` получает четвёртое поле:

```ts
export interface LearningSnapshot {
  streams: Stream[]
  materials: Material[]
  parts: MaterialPart[]
  notes: StudyNote[]
}
```

`emptyLearning()` возвращает `parts: []`.

### Какие поля живут у какого вида

| Вид | scale | pages_total / page_current | части | когда прогресс равен 100% |
|---|---|---|---|---|
| Книга, по страницам | `'pages'` | да | нет | `page_current >= pages_total` |
| Книга, по главам | `'parts'` | нет | главы | все части отмечены |
| Курс | `null` | нет | лекции | все части отмечены |
| Статья | `null` | нет | нет | `status === 'done'` |
| Видео | `null` | нет | нет | `status === 'done'` |

Последняя колонка — про полосу прогресса, а не про статус. **Статус меняется только
руками**, ни одна из этих величин его не двигает: дочитанная до последней страницы
книга остаётся `active`, пока её не закрыли. Обратное направление есть только у
статьи и видео, у которых полоса и есть статус: там тумблер на странице материала
пишет `status` напрямую.

Инвариант: части существуют только у книги со `scale === 'parts'` и у курса. Смена
вида или шкалы на такую, где частей нет, части удаляет. Если их больше нуля и хоть
одна отмечена — форма сначала спрашивает подтверждение; если все пусты — удаляет
без вопроса.

## 4. Хранилище

### Контракт

`LearningStore` получает три метода:

```ts
addPart(item: NewMaterialPart): Promise<MaterialPart>
updatePart(id: string, patch: Partial<MaterialPart>): Promise<void>
deletePart(id: string): Promise<void>
```

`NewMaterialPart = Pick<MaterialPart, 'material_id' | 'title' | 'done' | 'sort'>`.

`deleteMaterial` каскадом уносит части материала — как уже уносит его конспекты.
`deleteStream` уносит части материалов потока.

Массовое создание частей (двадцать глав одним действием формы) делается циклом
`addPart` в контексте, а не отдельным методом хранилища: один способ добавить часть
проще, чем два, а частей за раз — десятки, не тысячи.

### Миграция снимка v2 → v3

Ключ `readingtracker.learning.v3`. Прежние ключи не удаляются: пара килобайт против
единственной копии конспектов.

Порядок чтения: `v3` → `v2` → `v1`. Снимок `v1` мигрирует в `v2` уже существующим
кодом, затем `v2` в `v3` новым. Битые поля не роняют переезд — как и сейчас, каждый
массив проверяется на `Array.isArray`.

Правила `v2 → v3`:

1. **Виды.** `podcast` → `video` (смотрела или слушала — одна семантика, один
   тумблер), `other` → `article` (цельная штука, прочла или нет).
2. **Шкала книги.** Только для `kind === 'book'`: `parts_total > 0` →
   `scale: 'parts'`. Иначе `scale: 'pages'`, `pages_total: null`,
   `page_current: null`. У курса, статьи и видео `scale` остаётся `null`.
3. **Части.** Материал вида `book` со `scale: 'parts'` или `course` с
   `parts_total = N` получает N частей: `Глава 1…N` для книги, `Лекция 1…N` для
   курса, на языке текущей локали.
4. **Сохранение видимой цифры.** Пройденными помечаются первые
   `min(число конспектов материала, N)` частей. Смысл: человек видел «12 из 20» и
   после обновления должен увидеть то же самое. Это перенос показания, а не
   утверждение о том, какие именно главы пройдены, — поэтому отмечаются первые по
   порядку, а не угаданные по тексту конспекта.
5. **Статья и видео.** Ничего не меняется. Статус остаётся как был; материал с
   конспектами, но без `done`, так и останется непрочитанным, пока его не отметят.
   Автоматически проставлять `done` нельзя: конспект больше не значит «пройдено».
6. `parts_total` из объекта материала удаляется.

Запись мигрированного снимка защищена `try` — как и сейчас: недоступное на запись
хранилище не повод выбрасывать уже посчитанный снимок, годный для показа.

### Supabase

В этот заход не входит. Форма `MaterialPart` выбрана так, чтобы стать таблицей
`material_parts` без изменений, а числовые поля материала — колонками.

## 5. Прогресс

`materialProgress` переписывается. Четыре ветки вместо одной:

```ts
export interface MaterialProgress {
  done: number
  total: number | null
  percent: number | null
  /** Чем меряется — для подписи под полосой: страницы, главы, лекции или ничего. */
  unit: 'page' | 'part' | 'lecture' | 'flag'
}
```

| Вид | done | total |
|---|---|---|
| Книга, страницы | `page_current ?? 0` | `pages_total` |
| Книга, главы · Курс | отмеченных частей | всего частей |
| Статья · Видео | `status === 'done' ? 1 : 0` | `1` |

`total` равен `null`, когда книга по страницам не знает, сколько их всего, или когда
у книги/курса ещё нет ни одной части. Тогда `percent` тоже `null` и полоса не
рисуется — как и сейчас.

Величина «сколько написано конспектов» остаётся, но живёт отдельной функцией и
отдельной строкой на экране. Она больше не смешивается с прогрессом.

## 6. Форма материала

Одна форма на добавление и на редактирование, как и сейчас. Не визард: всё на одном
экране, поля появляются по мере того, как ответ на предыдущий вопрос делает их
осмысленными.

```
Новый материал                                  Отмена
──────────────────────────────────────────────────────
[Книга] [Статья] [Курс] [Видео]

Ссылка
[ https://…                              ]  [ ✨ ]
Заполню название, автора и обложку по ссылке

Название *   [                                  ]
Автор        [                                  ]

книга  →  Считать по  [Страницам] [Главам]
          Страниц [320]      ·или·      Глав [20]
курс   →  Лекций  [12]
статья, видео → ничего

Обложка
[превью 3:4]   Загрузить файл · Убрать

Куда  [Входящее] [В работу] [Когда-нибудь] [Справка]
──────────────────────────────────────────────────────
[Сохранить]                          Удалить материал
```

### Порядок и почему такой

**Вид — первым и без подписи.** Он определяет, какие поля вообще существуют ниже,
поэтому не может стоять в середине. Подпись над переключателем не нужна: четыре
слова «Книга, Статья, Курс, Видео» объясняют себя сами, а лишняя строка «Вид» только
отодвигает первое поле вниз.

**Ссылка — вторым.** Она умеет заполнить всё остальное, поэтому стоит до того, что
заполняет.

**Дальше только нужное.** Статья и видео не показывают ни одного поля о частях —
у них их нет.

### Звёздочка

Кнопка `✨` справа от ссылки. Значок `sparkles` добавляется в `Icon.tsx` — сейчас
такого нет.

По клику:

1. `localMeta(url)` мгновенно: домен, догадка вида по домену, обложка YouTube —
   она достаётся арифметикой из ссылки, без единого запроса наружу.
2. `fetchLinkMeta(url)` в сеть: YouTube oEmbed для заголовка и канала, microlink для
   остального.
3. Заполняются **только пустые поля**. Уже введённое руками не трогается.
4. Вид подставляется догадкой, **только если переключатель ещё не трогали руками**.
   Форма хранит флаг `kindTouched`.
5. Неудача — строка `material.fetchNothing`, не ошибка. Поля остаются как были.
6. `AbortController`: отменяется при размонтировании формы и при повторном клике.

Цена названа вслух строкой `material.fetchHint`: адрес материала уходит стороннему
сервису. Поэтому запрос идёт **только по явному клику**, никогда сам по себе — ни
на `onChange`, ни на `onBlur` поля ссылки.

### Статус

При создании — четыре корзины: `Входящее`, `В работу`, `Когда-нибудь`, `Справка`.
`Пройдено` и `Брошено` в форме добавления бессмысленны и не показываются.

При редактировании — все шесть.

### Части

В форме задаётся **число**, не список: набивать двадцать названий глав в попапе
никто не станет. Части создаются автоматически как `Глава 1…N` / `Лекция 1…N` и
переименовываются потом на странице материала, по одной, по мере надобности.

При редактировании, если число уменьшают, лишние части удаляются с конца — с
подтверждением, если среди удаляемых есть отмеченные. Если увеличивают — дописываются
в конец, существующие не трогаются.

### Проверки

`Название` обязательно. Числовые поля принимают только цифры. Пустое число — это
`null`, а не ноль: «не знаю, сколько страниц» и «ноль страниц» это разные вещи, и
только первое бывает на самом деле.

Поля `page_current` в этой форме нет — текущая страница живёт на странице материала
(раздел 9), потому что меняется она каждый раз, а всё остальное здесь — один раз.

## 7. Обложка

Три источника в порядке убывания предпочтения:

1. **По ссылке** — автозаполнение кладёт адрес в `cover_url`.
2. **Файлом** — новое.
3. **Нарисованная** — `MaterialCover` уже это умеет: цвет по названию, значок вида,
   домен внизу. Она же остаётся, когда чужой файл исчез.

### Загрузка файлом

Новый модуль `src/lib/learning/imageCover.ts`: файл → `createImageBitmap` → canvas →
кадрирование в 3:4 → ужатие до 400×533 → `toDataURL('image/jpeg', 0.8)` → в
`cover_url` как `data:`-адрес.

Ужимать обязательно. Снимок лежит в localStorage одной строкой JSON при лимите
около 5 МБ на origin; фотография с телефона в base64 съест его целиком и уронит
запись всего снимка, включая конспекты. 400×533 JPEG весит 30–50 КБ.

Ограничения: принимаются `image/*`, входной файл больше 10 МБ отклоняется до чтения
(понятной строкой, не молча). Результат больше 200 КБ — пережимается с качеством 0.6
и, если и это не помогает, отклоняется.

Тестируется арифметика кадрирования и выбора размера — чистой функцией, без canvas,
которого в jsdom нет.

## 8. Точки входа

| Откуда | Как | Поток |
|---|---|---|
| Дашборд потока | Кнопка `+ Материал` в шапке зоны «Что осталось» | Из адреса |
| Бэклог | Кнопка уже есть, ведёт в новую форму | Из адреса |
| Страница материала | `Настроить материал` | Свой |

`Zone` учится принимать действие рядом со ссылкой: сейчас у него есть только
`title` и `link`. Добавляется необязательный `action?: ReactNode`.

Выбора потока в форме нет нигде: во всех трёх точках он известен из адреса.

## 9. Страница материала

`Material.tsx` перестраивается под новую модель.

**Полоса прогресса** — по `materialProgress`, с подписью в единицах вида: `168 из 320
страниц`, `12 из 20 глав`, `3 из 12 лекций`. У статьи и видео полосы нет.

**Книга по страницам** — поле «на какой странице сейчас», сохраняется по `blur` или
по `Enter`.

**Книга по главам, курс** — список частей с чекбоксами. Название части
переименовывается на месте. Часть можно дописать в конец и удалить.

**Статья, видео** — один тумблер `Прочитано` / `Просмотрено`. Включённый ставит
`status: 'done'`, снятый — `status: 'active'`. Возврат именно в `active`, а не в
прежнюю корзину: снять отметку можно только с того, что уже открывали, а это и
значит «в работе». Прежний статус ради этого не запоминается — одно поле вместо
двух, и цена ошибки в один клик по корзине.

**Книга по страницам** — поле текущей страницы. Больше `pages_total` не принимает:
приравнивается к нему.

**Число конспектов** — отдельной строкой, рядом, но не внутри прогресса.

## 10. Общие компоненты

Три компонента в `src/components/ui.tsx`. Все формы переходят на них.

**`<FormStack>`** — то, чем сегодня является класс `.book-form`: вертикальный стек с
шагом 16. Класс переименовывается в `.form-stack` — имя `book-form` неверно с тех
пор, как в него завернули лист сессии и лист конспекта. Сейчас его ставят три формы
из пяти; `MaterialForm` и `StreamForm` обёртку просто забыли, отчего поля в них и
стоят вплотную. Компонент отнимает возможность забыть.

**`<Chip>`** — с `as?: 'span' | 'button'`. Сегодня это класс, который пишут руками то
на одном теге, то на другом. `.chip` получает `display: inline-flex; align-items:
center` — вот и вся причина разной высоты.

**`<Field label>`** — обёртка `<label class="field">` с `<span class="label">`, чтобы
эта пара не повторялась в каждой форме по восемь раз.

### CSS

- `.form-row` **удаляется**. Он объявлен гридом без колонок и ничего не выстраивает;
  рядом живёт `.field-row`, делающий то же правильно. Два класса для одного — и есть
  источник разнобоя.
- `.chip` получает `display: inline-flex; align-items: center; justify-content: center`.
- `.book-form` → `.form-stack`, все пять употреблений переезжают.
- `.seg` проверяется на шести статусах: при переносе на вторую строку `flex-wrap`
  даёт рваный ряд, тогда — `grid` с равными колонками.

### Sheet

Чинится руками, без библиотеки. В `Sheet.tsx`:

- фокус переносится в диалог при открытии — на первое фокусируемое поле;
- Tab и Shift+Tab заперты внутри диалога;
- при закрытии фокус возвращается на элемент, открывший лист;
- `overflow: hidden` на `body`, пока лист открыт, с возвратом прежнего значения.

Одно место — чинит все пять форм разом.

## 13. Чего в этом заходе нет

- Переезд лернинга в Supabase. Модель к нему готова, работа отдельная.
- Привязка конспекта к конкретной части через `part_id`. У части есть `id`, так что
  зацепиться будет за что, но пикер в `StudySheet` — следующий заход. До тех пор
  `StudyNote.part` остаётся свободной строкой.
- Сессии со страницами для книг лернинга, как в чтении.
- Связь материала-книги с книгой на Полке.
- Переименование частей списком в самой форме добавления.
