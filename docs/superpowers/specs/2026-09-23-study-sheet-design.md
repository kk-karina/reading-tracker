# Лист занятия — дизайн

Дата: 2026-09-23. Статус: реализовано. Расхождения с первой редакцией отмечены
по месту — спека правилась по ходу, а не после.

Лист «Записать занятие» (`src/components/learning/StudySheet.tsx`) — единственное
место, где занятие превращается в данные. Сегодня это три поля ввода: дата,
строка «Глава или часть» и конспект. Глава набирается руками, хотя у материала
уже есть список глав с названиями. Отметить главу пройденной из листа нельзя
вовсе. Конспект — `textarea`, в которой видны служебные знаки разметки.

Спека делает лист местом, где видно, за что ты села и что из этого закрылось:
глава выбирается из списка и отмечается пройденной здесь же, конспект получает
настоящее форматирование по выделению, а служебный заголовок уступает место
обложке материала.

Опирается на `2026-09-22-learning-materials-design.md` (виды материала, шкалы
прогресса, части как отдельная коллекция). Ничего оттуда не переопределяется —
наоборот, доводится до конца: части там заведены, а листу занятия про них не
рассказали.

## 1. Что не так сейчас

| Симптом | Причина в коде |
|---|---|
| Глава набирается текстом, хотя список глав есть | `StudySheet` держит `part` как `useState('')` и кладёт его в `NewStudyNote.part` строкой. Про `MaterialPart[]` лист не знает |
| Отметить главу пройденной из листа нельзя | `save()` вызывает `addNote` и, если нужно, `updateMaterial(status)`. `updatePart` не вызывается никогда |
| «Станет 3 из 12» — неправда | Строка `study.willBe` считает `next = p.done + 1`, но для книги по главам `materialProgress` берёт `done` из `parts.filter(p => p.done).length`, а лист этого числа не меняет. После сохранения на дашборде остаётся прежнее |
| Поле «Глава или часть» показывается и статье, и видео | Лист одинаков для всех видов. У статьи глав нет и быть не может (`hasParts` — только `course` и `book`/`parts`) |
| Прочитанную половину главы нечем выразить | `MaterialPart.done` — булево, и ставится оно только чекбоксом на странице материала. Состояния «начала, не дочитала» в интерфейсе нет ни в каком виде |
| Разметка видна глазами | `.note-input` — `textarea`. Жирный текст выглядит как `**жирный**` |
| «Выделить главное» не находится | Кнопка стоит в `.note-tools` над полем и работает только по уже сделанному выделению. До выделения она ничего не делает и никак об этом не говорит |
| Из четырёх нужных форматов доступен один | `NoteEditor.highlight()` умеет только `==…==`. `renderMarkdown` умеет ещё `**` и `*`, но поставить их можно только руками. Подчёркивания нет ни у того, ни у другого |
| Заголовок листа — служебное слово | `Sheet` принимает `title: string` и всегда рисует его в `h2.sheet-title`. «Записать занятие» занимает самое видное место и не сообщает ничего: ты и так знаешь, что нажала |
| Название материала стоит мелким серым | `<p className="small muted study-sheet-what">{material.title}</p>` — под заголовком, в подчинённой роли. Автора нет вовсе |

## 2. Ключевые решения

**Лист показывает то, чем материал меряется.** `materialProgress` уже возвращает
`unit` — `part`, `page` или `flag`. По нему лист и выбирает единственное поле
прогресса. Одно поле вместо одного поля — но всегда осмысленное.

**Галочка отражает состояние главы, а не действие над ней.** «Глава пройдена»
показывает, чем глава станет после сохранения, и потому включена и для
непройденной главы (по умолчанию), и для уже отмеченной. Формулировка «добавить
отметку» позволяла бы галочке разойтись с правдой; эта — не позволяет.

**«Начала, не дочитала» не заводит третьего состояния в данных.** Это
производная величина: у главы есть конспекты, но `done` не стоит. Хранить её
отдельно значило бы уметь рассинхронизировать её с конспектами.

**Конспект остаётся markdown.** Форматирование настоящее, хранение прежнее. Файл
конспекта читается глазами вне приложения, «мысль недели» продолжает ловить
`==…==`, старые записи открываются как есть, миграции нет.

**Волне достаётся `__текст__`.** Знака для волнистого подчёркивания в markdown
не существует. `__` выбран потому, что это чистый markdown: в чужом редакторе он
выродится в жирный — честная деградация, это тоже акцент. Вариант с буквальным
`<u>` в теле даёт точнее (Obsidian показал бы именно подчёркивание), но кладёт в
хранилище HTML, а `renderMarkdown` намеренно экранирует HTML первым действием.

**Форматирование живёт на выделении, а не на кнопке.** Постоянной кнопки не
остаётся. Меню вызывается правым кликом по выделению и дублируется панелькой,
всплывающей над выделением. Разница не декоративная: панелька находится без
подсказки и работает там, где правого клика нет, меню объясняет, что поле
умеет, и учит клавишам.

**Шапка листа — предмет, а не действие.** Обложка, название, автор. Слово
«Записать занятие» остаётся в `aria-label`: без него лист станет для экранного
диктора безымянным.

## 3. Глава и прогресс

### 3.1 Что показывает лист

| `unit` | материал | поле |
|---|---|---|
| `part` | книга по главам, курс | селект глав + галочка «пройдена» |
| `page` | книга по страницам | «дочитала до страницы», предзаполнено `page_current` |
| `flag` | статья, видео | галочка «прошла целиком» / «досмотрела» |

Слово в подписях берётся из `partWord(material.kind)`: у книги глава, у курса
лекция. У статьи и видео — `material.read` / `material.watched`, те же строки,
что уже стоят на странице материала.

### 3.2 Селект глав

Нативный `<select className="select">` — тот же элемент, что в `Journal.tsx:65`.
Нативный, а не свой список: он работает на телефоне, ищется набором с
клавиатуры и не требует собственной клавиатурной навигации.

Строка главы — состояние плюс имя из `partLabel(part, i, fallback)`, который уже
умеет звать неназванную главу её номером по порядку:

```
✓  Глава 1. Nobody Thinks Like You
◐  Глава 2. The Trouble with Maps
   Глава 3
   Глава 4
```

- `✓` — `part.done`
- `◐` — `notes.some(n => n.part_id === part.id)` и не `done`
- `○` — ни того, ни другого

Третий знак, а не пустое место: пустота не выравнивается по ширине с двумя
другими, и столбик состояний перестаёт читаться сверху вниз.

Знаки идут в текст `<option>`, а не в разметку: содержимое `<option>` рисует
операционная система, и ничего, кроме текста, туда не положить.

**Что выбрано при открытии** — первая начатая глава, иначе первая непройденная,
иначе последняя. Порядок именно такой: начатая важнее непройденной, потому что
на ней ты и остановилась. Ради этого правила селект и заводится — в обычном
случае выбирать не придётся вовсе.

Правило живёт чистой функцией `pickDefaultPart(parts, notes)` в
`src/lib/learning/parts.ts`, рядом с `partsOf` и `partLabel`: выбор главы — та
же арифметика списка частей, и проверяется она так же, без React.

Конспекты, написанные до этой спеки, `part_id` не имеют, и `◐` на их главах не
появится. Задним числом связать их с главами нечем: в `part` лежит свободный
текст, и совпадение с именем главы ничего не доказывает. Первое же занятие по
такой главе ставит метку.

**Если глав ещё нет** (у книги стоит «по главам», но список пуст) — на месте
селекта строка `study.noParts`. Своя строка, а не `material.partsHint`, как
стояло в первой редакции: та объясняет поле в форме материала («Необязательно.
Если указано, виден прогресс») и на пустое состояние не годится. Заводить главы из
листа занятия эта спека не берётся: это вторая задача в форме, у которой уже
есть своё место.

### 3.3 Галочка «глава пройдена»

Стоит под селектом, включена по умолчанию. Показывает состояние главы после
сохранения:

| выбрана глава | галочка при открытии | снять значит |
|---|---|---|
| не начата или начата | включена | не дочитала — оставить `◐` |
| пройдена (`✓`) | включена | передумала — снять отметку |

При смене главы в селекте галочка пересчитывается: для непройденной — включается,
для пройденной — остаётся включённой. То есть «включена» всегда, и это не
ошибка: непройденную ты сейчас проходишь, пройденная уже пройдена.

### 3.4 «Станет N из M»

Считается от галочки и от прежнего состояния главы:

```
delta = checked && !part.done ?  1
      : !checked && part.done  ? -1
      :                           0
next  = p.done + delta
```

Для `unit === 'page'` — от введённого числа страницы. Для `unit === 'flag'`
строка не показывается: там одно из одного, и предсказывать нечего.

### 3.5 Что пишется при сохранении

1. `addNote({ ..., part_id, part: null })`
2. `updatePart(part_id, { done: checked })` — только если `checked !== part.done`
3. Для `page`: `updateMaterial(id, { page_current })` — только если изменилось
4. Статус материала пишется один раз и одним значением, чтобы две записи не
   спорили между собой:

   | материал | новый статус |
   |---|---|
   | `flag`, галочка включена | `done` |
   | `flag`, галочка снята | `active` |
   | остальные, статус не `active` | `active` |
   | остальные, статус `active` | не трогаем |

   Нижние две строки — прежнее правило листа: записать занятие по материалу из
   бэклога значит сесть за него.

### 3.6 Данные

У `StudyNote` появляется `part_id: string | null`. Старое поле `part: string |
null` остаётся нетронутым: на нём висят все уже написанные конспекты и весь
свободный ввод, который был до этой спеки.

Отображение главы конспекта везде, где оно есть, идёт по правилу: есть `part_id`
и часть находится — зовём её через `partLabel`; иначе печатаем `part` как есть;
иначе главы нет. Переименованная глава подтягивает свои конспекты, удалённая —
оставляет их без главы, а не с висящим именем.

`NewStudyNote` получает `part_id` в свой `Pick`.

Локальное хранилище: поле nullable, снимок `readingtracker.learning.v3` остаётся
валидным, версия ключа не поднимается. При чтении — `part_id: n.part_id ?? null`.
Каскад удаления части конспекты не уносит: конспект переживает свою главу и
становится конспектом без главы.

### 3.7 Побочное: список глав на странице материала

`.part-row` получает третий вид — начатая. Иначе состояние, которое лист
научился создавать, не видно нигде. Маркер тот же `◐` перед именем, класс
`.part-row.started`.

## 4. Конспект

### 4.1 Поле

`<div contentEditable>` вместо `<textarea>`. Класс `.note-input` остаётся —
меняется тег, не место в вёрстке.

Ряд `.note-tools` лишается кнопки «Выделить главное» и остаётся только ради
чипов с метками. В листе занятия метки не приходят (`tags`/`onTags`
необязательны — см. комментарий в `NoteEditor`), поэтому там ряд исчезает
целиком, и лист начинается с самого поля.

**Tab.** Полю проставляется `tabIndex={0}`. Ловушка фокуса в `Sheet` собирает
элементы селектором, и `textarea` в него входила, а `contentEditable` — нет: без
этого Tab перепрыгивал бы через конспект, а на краю списка заворачивался бы
мимо него.

**Вставка из буфера** перехватывается и кладёт простой текст. Чужая разметка всё
равно не доедет до хранилища — `htmlToMd` отдаёт от незнакомых тегов только
текст, — а показывать оформление, которое исчезнет при сохранении, значит врать.

**Каретка.** Значение кладётся в поле один раз при монтировании. Из пропса поле
перерисовывается, только если `body` пришёл извне и не равен тому, что компонент
отдал последним через `onBody`. Без этого правила каретка прыгает в начало на
каждой букве — это главный способ провалить такой редактор.

Плейсхолдер — `:empty::before` с `note.bodyPlaceholder`: у `contentEditable`
своего плейсхолдера нет.

### 4.2 Четыре формата

| формат | знак | тег | клавиши |
|---|---|---|---|
| жирный | `**…**` | `<b>` / `<strong>` | ⌘B |
| курсив | `*…*` | `<i>` / `<em>` | ⌘I |
| волна | `__…__` | `<u>` | ⌘U |
| маркер | `==…==` | `<mark>` или `<span style="background-color">` | ⌘H |

Жирный, курсив и подчёркивание — родные команды при `execCommand('styleWithCSS',
false, '')`. Без этого флага браузер отдаёт `<span style>` вместо тегов.

Маркер — единственный без родной команды с предсказуемым тегом: `hiliteColor`
даёт `<span style="background-color">`. Сериализатор принимает оба варианта.
Если `hiliteColor` окажется ненадёжным, ручная обёртка `Range` включается для
него одного; три остальных остаются на `execCommand` и от этого не зависят.

`<u>` внутри `.note-input` рисуется жёлтой волной:
`text-decoration: underline wavy var(--lemon)`. Вне поля — в отрендеренном
конспекте — тем же правилом.

### 4.3 Меню

Одно меню, два вызова.

**Правый клик** по выделению внутри поля: `contextmenu` перехватывается,
`preventDefault`, меню в точке курсора. Пункты со словами и горячими клавишами.
Если выделения нет — не перехватываем ничего: системное меню с орфографией и
вставкой остаётся на месте.

**Панелька** из четырёх значков всплывает над выделением сама — через 150 мс
после последнего изменения выделения, чтобы она не гналась за курсором, пока
тянешь мышью. Позиционируется `position: fixed` по `getBoundingClientRect()`
диапазона: лист живёт в портале, и координаты относительно документа тут не
годятся.

Оба закрываются по Esc, по клику вне, по скроллу листа. На скролл — закрытие, а
не пересчёт позиции: пересчёт стоит дороже и в списке из четырёх значков не
нужен.

Активное состояние пункта (`document.queryCommandState`) показывает, стоит ли
формат на выделении, — тогда нажатие снимает его.

### 4.4 Сериализация

Две чистые функции в `src/lib/learning/noteHtml.ts`:

- `mdToHtml(md: string): string` — из хранимого markdown в разметку поля
- `htmlToMd(root: HTMLElement): string` — обратно

`mdToHtml` — не `renderMarkdown`: тот рисует конспект для чтения (заголовки,
цитаты, списки, ссылки), а поле редактирует плоский текст с четырьмя строчными
форматами. Блочная разметка внутри поля остаётся текстом со своими знаками и
переживает круг без изменений.

`htmlToMd` обходит дерево и знает: `b`/`strong` → `**`, `i`/`em` → `*`, `u` →
`__`, `mark` и `span` с непустым `background-color` → `==`, `br` и `div`/`p` →
перенос строки, остальное — текст узла. Незнакомые теги, приехавшие вставкой из
буфера, теряют оформление и отдают текст: это лучше, чем пустить в хранилище
чужой HTML.

Тесты — круговой прогон `md → html → md` на всех четырёх знаках, на вложенности
(`**жирный с ==маркером== внутри**`), на пустых обёртках и на тексте со знаками,
которые форматом не являются (`2 * 2`, `a__b`).

### 4.5 Что остаётся нетронутым

`renderMarkdown` получает правило `__…__` → `<u>`, поставленное после `**` и до
одиночной `*`; `plainText` — соответствующее снятие знаков. Всё остальное там не
меняется. `extractHighlights` продолжает искать `==` и про редактор не знает,
«мысль недели» работает как работала.

## 5. Шапка листа

`Sheet` получает необязательный `head?: ReactNode`. Есть `head` — рисуется
вместо `h2.sheet-title`. `title` остаётся обязательным всегда и продолжает
работать `aria-label`.

Правка в общем месте, а не своя шапка внутри `StudySheet`: четыре остальных
листа не меняются ни строкой, и следующий лист, которому понадобится предмет в
заголовке, возьмёт готовое.

`StudySheet` отдаёт в `head`: `<MaterialCover material={material} size="md" />`,
рядом название в начертании `display` с переносом, под ним автор `small muted`.

Размер `md`, а не `sm`, как стояло в первой редакции: обложкой книги 38 пикселей
не выглядят. Но `md` рисует внутри себя название, и рядом с заголовком оно
выходило дважды, — поэтому в `.sheet-subject` подпись внутри обложки скрыта тем
же правилом, что уже есть у `.mcover-sm`.
Автора может не быть — тогда строки нет.

Обложка уже умеет всё нужное: картинку по `cover_url`, нарисованную подложку под
ней со значком вида и цветом по названию, подмену собой, когда чужой файл
исчез.

Строка `<p className="study-sheet-what">` убирается — название переехало наверх.
Кнопка «Отмена» справа в `.sheet-head` остаётся.

Переписаны две существующие строки. `note.bodyPlaceholder` больше не учит
набирать `==главное==` — знаки ставит выделение. `notes.empty` говорила «глава
считается пройденной, когда по ней есть конспект» — это прежнее правило, которое
эта спека и отменяет.

`note.highlight` и `note.part`/`note.partPlaceholder` остаются в словаре, пока
на них кто-то ссылается; вышедшие из употребления убираются в той же правке —
пропуск строки ловит `tsc`, лишнюю не ловит никто.

## 7. Чего эта спека не делает

- Не трогает `SessionSheet` — лист сессии чтения. Шапка с обложкой ему пошла бы,
  но это отдельное решение про другой раздел.
- Не заводит главы из листа занятия.
- Не хранит прогресс внутри главы числом. «Начала» и «дочитала» — два
  состояния, третьего в данных не появляется.
- Не переносит редактор на `Range` целиком. `execCommand` формально устаревший,
  и это известный долг; переезд локален, потому что сериализатор от способа
  правки не зависит.

## 8. Проверка

```
export PATH="$HOME/.nvm/versions/node/v24.15.0/bin:$PATH"
./node_modules/.bin/tsc -b
./node_modules/.bin/oxlint
./node_modules/.bin/vitest run
./node_modules/.bin/vite build
```

Новые тесты: `noteHtml.test.ts` (круговой прогон), `parts.test.ts`
(`pickDefaultPart` на пустом списке, на списке без начатых, на списке целиком
пройденном), и проверка предсказания «станет N из M» от галочки — там же, где
живёт сама арифметика.

Пройдено в браузере (Chrome, `playwright-core` без своей сборки): лист открылся
на начатой главе, все четыре формата легли и панелькой, и горячей клавишей, и
правым меню, в хранилище уехало `==Запасы== __меняются__ **медленно**`, глава
отметилась пройденной, «Станет 2 из 4» сошлось. Отдельно проверены книга по
страницам, статья и материал без глав — ошибок в консоли ни в одном случае.

Осталось руками — то, что автоматикой не поймать: каретка не прыгает при наборе, правый клик
без выделения отдаёт системное меню, панелька встаёт над выделением в
проскроленном листе, вставка из буфера не роняет чужой HTML в хранилище.
